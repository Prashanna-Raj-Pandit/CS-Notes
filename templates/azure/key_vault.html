Security & Secrets Management

Azure Key Vault + Databricks Secrets

How to store a secret securely in Azure Key Vault, expose it to Azure Databricks through a Key Vault-backed secret scope, and retrieve it with dbutils.secrets.get().

Secret Storage Azure Key Vault Holds the actual secret value
→
Bridge Secret Scope References the vault, holds no value itself
→
Notebook dbutils.secrets.get() Retrieves the secret at runtime

The secret itself never leaves Key Vault — Databricks only ever holds a reference to it.

Architecture Overview

The goal is to keep sensitive credentials out of notebooks and source control while still allowing Databricks workloads to access them when needed.

Azure Key Vault
↓
Secret: my-client-secret
↓
Databricks Key Vault-backed Secret Scope
↓
Scope: azure-keyvault-scope
↓
Databricks Notebook
↓
dbutils.secrets.get(...)
Key idea

Azure Key Vault stores the actual secret. Databricks uses a secret scope to reference the vault, and notebook code retrieves the secret by scope name and key.

1. Create the Azure Key Vault

Using Azure CLI:

create the vaultAzure CLI
az keyvault create \
  --name my-data-keyvault \
  --resource-group my-resource-group \
  --location centralus

Then add a secret:

store the secret valueAzure CLI
az keyvault secret set \
  --vault-name my-data-keyvault \
  --name my-client-secret \
  --value "YOUR_SECRET_VALUE"
ItemExample
Key Vaultmy-data-keyvault
Secret namemy-client-secret
Secret valueYOUR_SECRET_VALUE
Security note

Never put the real secret value in Git, a notebook, screenshots, documentation, or other public content.

5. Verify the Secret Scope in Databricks

List the secret scopes available to the notebook:

list available scopesPython
dbutils.secrets.listScopes()

You should see a scope such as:

expected resultOutput
azure-keyvault-scope

Then list the secrets available through that scope:

list secrets in this scopePython
dbutils.secrets.list("azure-keyvault-scope")

This lists the secret names or metadata, not their plaintext values.

For this example, you should find:

expected resultOutput
my-client-secret

6. Retrieve the Secret in a Databricks Notebook

Use dbutils.secrets.get():

retrieve the secretPython
client_secret = dbutils.secrets.get(
    scope="azure-keyvault-scope",
    key="my-client-secret"
)

The mapping is simple:

parameter mappingReference
scope = Databricks secret scope name
key   = Azure Key Vault secret name

A slightly larger example:

using both values togetherPython
client_id = "your-client-id"

client_secret = dbutils.secrets.get(
    scope="azure-keyvault-scope",
    key="my-client-secret"
)
Do not print secrets

Avoid commands such as print(client_secret). Databricks may redact secret values in some notebook output, but redaction should not be treated as a complete security boundary.

Common Use Cases

This pattern is useful when Databricks code needs credentials for:

  • Azure Data Lake Storage (ADLS)
  • Azure SQL databases and data warehouses
  • REST APIs
  • Service principals
  • JDBC connections
  • Other systems that require passwords, access tokens, or keys
